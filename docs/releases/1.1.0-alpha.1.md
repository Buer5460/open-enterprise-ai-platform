# OEAP v1.1.0-alpha.1

Status: **Alpha prerelease**

Stable security-review baseline remains: **v1.0.0-rc.2**.

This release freezes the first OEAP 1.1 usability/Marketplace development baseline after the 1.0 RC contract freeze.

## Release goals

`v1.1.0-alpha.1` answers a practical question: can a business team install OEAP and start doing useful work before every AI, SSO and payment integration is configured?

The intended answer for this alpha is yes.

## Day-1 application path

- One-click CRM, travel-agency, payment-service ERP and project/task templates
- Real generated App Packages, pages and SQLite business data
- Server-side CRUD field validation
- Business-data overview
- CSV/JSON import/export
- Dry-run migration validation
- Transactional batch import
- Application archive/restore while preserving the business database

AI is optional for this path.

## Daily workspace

- Application and entity search
- Member favorites
- Recently used applications
- Member-scoped personal folders/categories
- Smart/recent/name/folder sorting
- Server-side persistence by organization/member
- Legacy preference-schema migration

## AI Runtime

Two Provider paths are supported:

- DeepSeek Harness
- OpenAI-Compatible API

Provider selection:

- `auto`
- `deepseek-harness`
- `openai-compatible`

OpenAI-Compatible configuration can be stored per organization in the encrypted Connector Vault. API keys are not returned to the browser after storage.

Compatible-provider behavior is tested with controlled local mock servers; public CI does not require or expose real third-party model credentials.

## Marketplace foundation

This alpha includes:

- Marketplace Registry protocol/runtime
- public listing discovery/read APIs
- official seeded Agent/Package listings
- buyer-facing Marketplace UI
- organization-scoped free acquisition
- organization-scoped order and entitlement persistence

Paid plans create pending orders only. The public browser API does **not** expose the internal order-completion method and cannot self-grant a paid entitlement. A future trusted payment Connector/server-to-server webhook flow is required for production paid checkout.

## Production/readiness work

- Production Preflight understands both AI Provider paths
- explicit incomplete OpenAI-Compatible configuration fails closed
- no AI in `auto` mode is a warning, not a core-platform deployment blocker
- `OEAP_DATA_DIR` is documented as the durable production runtime root
- five-minute first-use documentation is included

## Quality gate

Before GitHub Release creation, the Release workflow must independently rerun:

- frozen-lockfile install
- release-version contract
- full workspace build
- deterministic regression suite
- built API and Day-1/data/AI/Marketplace tests
- real headless Chrome E2E
- Docker Compose validation
- API container build
- Web container build
- source archive generation

The GitHub Release is created only if those gates succeed.

## Not claimed by this alpha

This alpha does not claim completion of external/deployment-owned controls:

- independent security review
- production OAuth/OIDC credentials
- production DNS/TLS
- real production backup/restore drill
- third-party paid Marketplace payment processor/webhook
- production mail credentials
- real AI Provider credentials when AI is required

Those remain deployment/integration responsibilities and must not be represented as already validated by repository CI.
